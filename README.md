# MPlayer

MPlayer is being developed as an offline-first music player. The React/Vite interface is shared with a Tauri 2 application; native capabilities are implemented in Rust rather than simulated by the browser UI.

## Architecture (current stage)

- **UI:** React + TypeScript + Vite.
- **Native host:** Tauri 2 in `src-tauri/`.
- **Native playback (initial):** Rodio/CPAL with Symphonia decoding for formats enabled by the dependency. Playback currently uses the operating system's default output stream. A 10-band peaking-EQ source is implemented in Rust and reads live settings between audio frames.
- **Local storage:** SQLite in the operating system's application data directory. The native library index, playlist CRUD/membership, and LRC text save/load now use SQLite commands.
- **Desktop library scanning:** The user chooses a folder through a native dialog; Rust recursively indexes supported extensions, skips symbolic links, reads common embedded tags/audio properties through Lofty where supported, and caps each scan at 20,000 files. Completed scans reconcile removed files; a capped/incomplete scan does not prune unseen records.
- **Browser preview:** Web Audio remains the browser-only preview path. It is not a native audio implementation.

## Run the desktop app on Windows

Prerequisites: Node.js LTS, Rust stable using the MSVC toolchain, Microsoft C++ Build Tools with **Desktop development with C++**, and the WebView2 Runtime.

From the repository root in PowerShell:

```powershell
npm install
npm run tauri:dev
```

To build a native executable locally:

```powershell
npm run tauri:build
```

The installer/bundle is intentionally disabled while the native shell is being validated. The immediate goal is a working development build first; app icons, signing, installer packaging, and release automation are separate tasks.

## Mobile target preparation

Tauri requires the Android SDK/NDK and Java toolchain for Android. iOS builds require macOS with Xcode. After those prerequisites are installed:

```powershell
npm run android:init
npm run android:dev
```

On macOS:

```sh
npm run ios:init
npm run ios:dev
```

Mobile targets still need device/emulator verification. The current folder scanner uses a desktop folder picker; Android Storage Access Framework and iOS Files document-picker flows are not wired yet. Background playback, lock-screen/media-session controls, mobile lifecycle behavior, and mobile packaging/signing are also not yet verified.

## Known limitations — do not treat these as implemented

- Audio is routed through the default OS output. **WASAPI exclusive mode, device-specific output selection, sample-rate negotiation, bit-perfect output, and output diagnostics are not implemented or verified.**
- The scanner records file path, filename/tag-derived title, artist, album, extension, size, modification time, and common audio properties when Lofty can read them. Album artwork ingestion, year metadata, embedded cue sheets, detailed DSD metadata, and broader tag-format coverage remain pending.
- DSD (`.dsf`/`.dff`) files can be indexed, but the current Rodio/Symphonia decoder does not provide DSD decoding. Do not assume those files will play yet.
- The 10-band peaking EQ runs in the Rust sample source, and its settings are persisted in SQLite. Its frequency response, transition artifacts, clipping behavior, and long-run performance still require listening tests across sample rates and devices. EQ is sample processing, so **bit-perfect output cannot be claimed while EQ is enabled**.
- Native playlist creation/rename/delete, playlist membership, and LRC text save/load use SQLite. Playback history and last-position persistence are wired to SQLite and a native-only “Terakhir Diputar” library filter; resume-on-reopen and history UI edge cases still need device testing.
- The Windows icon is generated by `scripts/generate-native-icon.mjs` before Tauri dev/build commands and the Windows native CI check. Android/iOS project generation and generated mobile icon assets still need to be run and validated on their respective SDKs/devices.
